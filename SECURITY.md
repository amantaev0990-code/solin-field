# Безопасность SOLI-N Field

## Ответственное сообщение о проблеме
Не публикуйте сообщения об уязвимостях, токены, ключи подписи и данные лесничеств в открытых Issues или Pull Requests. Используйте приватное сообщение владельцу проекта либо GitHub Private Vulnerability Reporting, если оно включено.

## Основные правила
- Исходный код и данные для коммерческой разработки должны храниться в приватном репозитории. Этот публичный репозиторий исторически содержит код и не должен рассматриваться как защищённое хранилище.
- Ключ APK-подписи V23 должен оставаться неизменным для штатных обновлений; пароль и оригинальный ключ не добавлять в Git, документы, логи или чат.
- Публикуемый APK должен проверяться по SHA-256, package ID, увеличению versionCode и постоянному сертификату V23; сборку проверять на тестовом планшете.
- Перед выпуском проверить лицензии встроенных библиотек, справочников и картографических материалов.
- Полевая информация, Transfer MDB, фотографии, GPS и клиентские базы не должны попадать в публичные исходники.
- Защищённый архив исходников хранить отдельно. Пароль не должен храниться рядом с архивом.
- Включить 2FA/passkey для GitHub; ограничить доступ соавторов; не предоставлять сторонним сборкам долгоживущие токены.

Запуск локальной базовой проверки: \`node scripts/security-gate.cjs\`.
Она помогает не добавить случайно секреты, но НЕ очищает старую Git-историю и НЕ заменяет аудит.
