# SOLI-N Field — единая система зависимых справочников

Дата анализа: 02.11.2026. Исходный источник: `solin-dictionary.js → originalForms[*].combos` и реальные таблицы `refs-audit.json.gz`. Из 84 описанных списков оригинальных форм в 25 обнаружены явные условия `WHERE`, `Forms!`, исключения, фильтры или логика последовательного ввода. Другие списки могут иметь зависимости из VBA-событий: отсутствие `WHERE` не является доказательством независимости.

## Общий контракт

1. Выбираем *контекст* — лесничество (POS/LESN/KTO), квартал (KV/KGLF/Kpz/Klxr/Fzona), выдел (KU/M3Pr/NE2A), строку макета и предшествующие поля.
2. Вычисляем допустимые варианты из **оригинальных** таблиц (сохранённые шифры не нормализуем).
3. Отображаем только допустимые позиции; при недостающем контексте не показываем полный справочник под видом разрешённых значений.
4. Старый введённый/импортированный шифр, отсутствующий в результатах, виден как «сохранённый, сейчас недопустимый», но не включён в допустимый перечень; нет скрытой замены.
5. Изменение родительского поля пересчитывает зависимые селекторы, изменение строки не затрагивает другие выделы. Для применения требуется штатное сохранение.

Контракт реализован в `SolinDependentRules.options`, `SolinDependentRules.applySelect`, используется в настольной по виду карточке, отдельном редакторе макета, редакторе существующего квартала и форме нового квартала. Мобильный быстрый ввод берёт значения из соответствующего фильтрованного select.

## Что ещё НЕ подтверждено полностью

- `Квартал.Fzona`: архивная таблица `SFZ` содержит 15 строк и явные поля `KLF` (категория ГЛФ), `KFZ` (функциональная зона) и наименование. Теперь в **корректировке и создании квартала** отображаются только найденные **кандидаты по равенству SFZ.KLF=Квартал.KGLF**; для других категорий общий список не предлагается. Это **предварительные подсказки**, а не нормативная проверка: полный `WHERE` Access обрывается.
- `Квартал.Raion`: оригинальная таблица `Кл_Рай` отсутствует в сохранённом нормативном пакете, а предикат `ТЕОб` обрывается. В редакторе показано это ограничение; список административных кодов чужого лесничества не выдаётся за норматив. Полного фильтра пока нет.
- `Макет17.P17` и `Макет19.ZP`: из Access точно читается `SDP.DKP2 = 0 OR SDP.DKP2 > 70…`. Появились **частичные** списки с этим необходимым широким условием, но возможный более строгий порог из потерянного SQL неизвестен. Они помечены «не подтверждено», не используются для автоматического признания кода допустимым и не блокируют сохранение на основании неполного правила.
- Встроенные VBA `OnCurrent/OnExit/AfterUpdate` и зависящие от них поля вне извлечённых SQL — отдельный этап сверки с оригинальной базой.

Пока точный первоисточник для этих четырёх правил не доступен, программа не должна утверждать, что их первоначальный статический список полностью совпадает с настольным SOLI-N. Не расширяем фильтры догадками.

## Проверки

`scripts/test-contextual-comboboxes.cjs` сверяет физические ключи Slxr × Szap: для KTO=350000000 и Kpz=2 разрешены только 3/4/7, для Kpz=3 — 10. Также проверяются KGLF, Kpz, выбор ярусов, связанная порода Макета16, типы повреждений и последовательность мероприятий. `scripts/test-stock-autocorrection-ui.cjs` запускается в Chrome и воспроизводит реальные формы квартала/выдела, а `scripts/test-dependent-field-rules.cjs` проверяет исходные правила для макетов и состава.

**Критерий завершения всей задачи:** каждый селектор оригинального SOLI-N инвентаризирован, статический либо динамический; для каждого динамического известно точное исходное условие, проверен мобильный и основной ввод, а неправильные/неоднозначные сочетания не проходят сохранение. Этот критерий пока не выполнен для всех 84 списков.

## Дополнение: проверка реальных данных и Android APK — 02.11.2026

После базового переноса зависимых справочников реализована общая проверка `SolinDependentRules.validateTransition`: изменение/удаление полей в полной карточке и отдельных макетах 10, 12, 16, 23, а также смена главной породы, типа леса, мероприятий, подроста и подлеска проходит один источник правил. Старые не изменённые противоречия в импортированных карточках не блокируют постороннюю правку.

`SolinDependencyAudit` проверяет один выдел, квартал или целое лесничество, обходит большие наборы записей порциями и выдаёт **две разные категории**: доказанные нарушения исходного RowSource и значения, которые нельзя подтвердить из-за отсутствующих / неполных источников. Результат доступен как полный JSON и как UTF-8 CSV для Excel. Формульные выражения во входных полях CSV экранируются. Режим не изменяет записи. Проверка `Макет16.Por16` зависит от фактического `Макет10.POR` и работает даже без отдельной таблицы наименований SDP; отсутствие SSP/SBR/SLM/SOV/SDP_Tip больше не создаёт ложных ошибок.

**Сборка Android:** `android-actions/setup-android@v3` не должен устанавливать удалённый пакет SDK `tools`; сборка Capacitor не должна включать одновременно одинаковые `.gz` и несжатые WASM-файлы. Добавлен этап проверки staging: оригинальные базы MDB/ACCDB не включаются, кроме проверенного пустого шаблона. Прохождение сборки debug APK подтверждает компиляцию, **но не установку, корректность чтения/записи MDB на смартфоне или готовность к эксплуатации в предприятии**.

Ограничения исходных запросов `Fzona`, `Raion`, `Макет17.P17`, `Макет19.ZP` и неподтверждённый VBA остаются открытыми. Их нельзя считать реализованными по одному лишь наличию общих справочников.

## Нативная проверка MDB в Android-эмуляторе

В `native/android/SolinMdbInstrumentedTest.java` добавлены два теста **того же кода Jackcess**, который вызывается из `SolinMdbPlugin.export`: запись трёх адресных таблиц и `Макет10` в копию проверенного пустого MDB с повторным открытием и сверкой полей; отказ от записи строки чужого лесовладельца с побайтовым подтверждением отсутствия изменений при отказе. В `scripts/install-android-mdb.mjs` добавлена установка теста и AndroidX JUnit-зависимостей в генерируемый Capacitor-проект. Запуск: `.github/workflows/solin-android-native-tests.yml` на эмуляторе Android API 35.

**Тест на эмуляторе не является проверкой на физическом смартфоне** и не подтверждает весь путь системного выбора файла или импорта реального лесничества. Для этого понадобится отдельное испытание с собственным тестовым MDB.

**Форма нового квартала:** дополнена полями `Fzona` и `Raion` (прежде были доступны только при последующем редактировании). Для `Fzona` подсказки перестраиваются после выбора `KGLF`, значение не проставляется автоматически. В `Raion` разрешён ручной ввод проверенного шифра, но источник отсутствует и автоподбор не выполняется. Проверка браузером охватывает оба поля и отсутствие произвольной автоподстановки.
