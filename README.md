# SOLI-N Field

Мобильное полевое приложение для таксации леса на основе настольного SOLI-N.

**[Открыть приложение](https://amantaev0990-code.github.io/solin-field/)**

## Рабочие данные

Лесовладельцы и лесничества хранятся раздельно. Можно импортировать оригинальный Transfer MDB, создать своё лесничество, редактировать кварталы и выделы, работать со справочниками и картами, выполнять контроль карточек. Данные пользователя сохраняются локально в браузере (IndexedDB); изменение рабочего пространства не перезаписывает исходный файл.

Разделы о совместимости, функциях и контроле: [Workspaces](WORKSPACES_AND_READABILITY.md), [контроль SOLI-N](NATIVE_CONTROL.md), [архитектура APK и MDB](APK_AND_MDB_ARCHITECTURE.md).

## Единая кнопка «Экспорт»

В SOLI-N Field на странице **«Ещё»** для браузерной версии теперь одна кнопка **«Экспорт»**. Нажатие сохраняет выбранное лесничество в IndexedDB и открывает отдельный локальный .NET WebAssembly-движок с автоматическим созданием настоящего Jet MDB. Файл предлагается с исходным названием `Transf_<POS>_<LESN>_<GodT>.mdb` без суффикса Field и без префикса TEST_. В Safari после завершения автоматически запускается скачивание, а на случай ограничения iOS остаётся ссылка «Сохранить MDB». Вручную запускать тест или выбирать шаблон больше не нужно. Никакие карточки на сервер не отправляются.

**Ограничение совместимости:** новый движок сохраняет 18 поддерживаемых таблиц, тогда как оригинальный Transfer содержит 29 операционных. Генерируемый файл проверяется обратным чтением на устройстве, но полноценный приём старым SOLI-N ещё не подтверждён. Первый приём делайте только на резервной копии базы. Экспорт базы с неподдерживаемыми дополнительными таблицами блокируется, а не выкидывает их.

## Предыдущий браузерный экспорт CheerpJ (сохранён как резервный механизм)

**«Ещё» → «Экспорт» → сохранить готовый `.mdb`. Никаких окон «Выбрать файл» и загрузки исходного MDB.** Приложение автоматически скачивает проверенный пустой Access Jet MDB, сформированный в GitHub Actions из структуры 18 известных таблиц SOLI-N Field. Шаблон содержит **ноль записей**, без пользовательских данных, и заполняется текущими карточками на телефоне. Проверяются двоичный формат, таблицы, число строк и значения. Название файла — оригинальное `Transf_<POS>_<LESN>_<GodT>.mdb` (например, `Transf_213_2_2026.mdb`) без приписки Field.

Исходная база SOLI-N при выгрузке не используется и не изменяется; пользователь не загружает никакой файл. Типы **279 столбцов 18 экспортируемых таблиц** сверены с оригинальным `Transf_213_2_2026.mdb` и хранятся отдельно в `data-transfer-types.json`. В частности, `Выдел.PRkol` — FLOAT и сохраняет `0.6`, а `Выдел.VD` — TEXT. При этом оригинальный Transfer содержит больше таблиц (29 операционных), чем представлено в текущем экспорте (18). Файл будет настоящим Jet MDB, но гарантировать приём настольным SOLI-N пока нельзя. Проверяйте только на тестовой копии.

Исходный код Java движка: `mdb-service/src/main/java/kz/solin/mdb/TransferWriter.java`. Генерация пустого MDB: `BlankTransferTemplate.java` и `scripts/prepare-blank-mdb.mjs`. Автоматическая публикация: `.github/workflows/build-browser-mdb.yml`. Публичный шаблон: `vendor/solin-empty-transfer-v20261028-27.mdb`. CI проверяет отсутствие строк, 279 исходных типов, 18 таблиц, запись/повторное чтение 1243 тестовых записей и отдельно дробное значение `PRkol = 0.6` в строке 226; запуск в Safari и штатный приём настольным SOLI-N ещё предстоит проверить.

Java-движок CheerpJ 4.3 загружается с внешнего CDN, поэтому полностью автономный экспорт на iPhone не гарантирован. Для организационного использования CheerpJ надо отдельно проверить условия лицензирования.

## Android APK и резервный вариант для Windows

Android-реализация использует тот же HTML/JS интерфейс и экспериментальный нативный Jackcess-плагин в `native/android/SolinMdbPlugin.java`. Сборка APK и проверка реальной совместимости экспорта на устройстве ещё необходимы.

Вспомогательный `solin-mdb-bridge.js` позволяет подготовить ZIP с JSON и скриптом `windows/Build-SOLIN-Transfer-MDB.ps1` для конвертации в настоящий MDB на Windows с установленным Access/DAO. **ZIP не является MDB**, а эта функция не заменяет прямую кнопку экспорта на iPhone. Серверный прототип `mdb-service/ExportServer.java` не развёрнут и не нужен браузерной кнопке.

## Что ещё нужно проверить

- Экспорт на настоящем iPhone/Safari, включая повторную выгрузку без выбора шаблона.
- Совпадение всех операционных таблиц, полей, типов, ключей, родственных макетов и значений с оригинальным Transfer. Автоматические Java-тесты проверяют синтетические базы, а не все варианты оригинального SOLI-N.
- Открытие полученного MDB в Microsoft Access и штатный приём в настольном SOLI-N **только на резервной копии**.

До этих испытаний функция остаётся экспериментальной. Не заменяйте настоящие производственные MDB экспортом SOLI-N Field.

### Верификация экспорта в Safari — версия v28

В браузерном окружении CheerpJ возникала ошибка просмотра «В файле не указано ни одного лесничества», хотя Java возвращала код завершения 0. Поэтому каждый экспорт создаётся в уникальной папке виртуальной файловой системы (исключает старую копию с тем же именем). После записи Java повторно открывает MDB, проверяет количество записей каждой таблицы и записывает служебный SHA-256 отчёт о файле в ту же папку. JavaScript проверяет совпадение SHA-256, длины, шифров лесовладельца/лесничества/года и количества записей.

Если после всех этих сверок независимый Safari-парсер всё же сообщает только об отсутствии записи «Лесничество», интерфейс позволяет сохранить **тестовый** MDB с предупреждением, что требуется открыть файл в настольном SOLI-N **исключительно на резервной базе**. При несоответствии контрольной суммы, ошибке Java, неверных числах или несовпадении данных выгрузка блокируется. Это диагностический режим, а не подтверждённая полная совместимость с настольным SOLI-N.

В CI добавлено независимое чтение заполненного Jackcess MDB через фактическую JavaScript-библиотеку Safari (`scripts/check-browser-mdb.mjs`). В JVM тест проходит; различие проявляется только на iPhone в цепочке виртуальной ФС/Blob, поэтому тест на телефоне остаётся обязательным.
