# CMF2 structural-v4 — зафиксированный рабочий baseline

Дата фиксации: 2026-09-08.

Это текущая эталонная архитектура импорта CMF2 для SOLI-N Field. Не заменять её каскадом старых эвристических декодеров без отдельного регрессионного теста.

## Геометрия — не менять без регрессии

- Рабочее ядро геометрии: `cmf2-structural-v4.js`.
- Геометрические потоки ищутся независимо от описателей слоёв.
- Связь `layer descriptor -> SpatialBlock` определяется структурным инвариантом масштаба envelope/quantized bbox.
- Поддерживаются одно- и многоблочные raw-LZ4 потоки с framed length metadata.
- Режим delta-кодирования выбирается по собственным bbox объектов, а не по визуальному совпадению слоёв.
- Пользователь подтвердил на ранее неизвестном CMF2, что после перехода на structural-v4 слои встали на свои места. Геометрическое ядро после этого не менять при исправлении подписей/атрибутов.

Контрольные CMF2:
- Богетсайское: 7/7 векторных слоёв, 904 объекта, 39 799 вершин; stand = 322 объекта.
- Комсомольское: 7/7 слоёв, 1 352 объекта, 71 641 вершина; stand = 448 объектов.

Оба файла являются регрессионными эталонами.

## Прямые атрибуты слоя `ВыдПород` — подтверждено побайтно

Повторный разбор stand-storage обоих контрольных файлов показал: необходимые для CarryMap-карточки атрибуты лежат не только в PSTG/SQLite/FTS4. Они записаны как отдельные framed raw-LZ4 column streams рядом с SpatialBlock. Поэтому основной путь отображения атрибутов теперь не зависит от успешной реконструкции SQLite.

Строковый вектор имеет структуру:

`[N LEB128-кодов длины][N UTF-8 строк подряд]`

Значение LEB128-кода равно примерно `byteLength << 1` (младший бит используется как флаг). Для коротких строк код занимает 1 байт, для длинных — несколько байт. Это объясняет, почему `Ключ` можно было прочитать однобайтным вариантом, а длинную `Категорию защитности` — нет.

На обоих эталонах подтвержден стабильный порядок строковых колонок stand-слоя:
1. `Лесничество`
2. `КатЗащ`
3. `КатЗем`
4. `Тип_леса`
5. `Порода`
6. `ПородаПП`
7. `ХозРаспор1`
8. `ХозРаспор2`
9. `Ключ`

`Ключ` содержит готовые значения `квартал_выдел`, например `70_5`, `69_2`, `92_1`. Проверка:
- Богетсайское: 322/322 уникальных ключа;
- Комсомольское: 448/448 уникальных ключей.

Между строковыми колонками лежат фиксированные числовые векторы. Подтверждено прямым декодированием:
- `Nкварт` — Float64;
- `Nвыд` — Float64;
- `Площ` — Float32;
- `Бонитет` — Float64;
- `Тон` — Float64;
- `А_лет` — Float64;
- `Н_м` — Float64;
- `Д_см` — Float64;
- `Полн_прижи` — Float32;
- `Запас_м3_г` — Float64;
- `Проц1/Проц2` — Float64, при полностью пустой/нулевой колонке отдельный builder может хранить её сокращённо;
- `МасУч` — Float64;
- `Обход` — Float64.

У фиксированных числовых колонок значения находятся в хвосте распакованного блока; перед ними находится небольшой служебный prefix/bitmap. Длина хвоста строго равна `N*8` для Float64 или `N*4` для Float32.

Перед geometry SpatialBlock также найдены два целочисленных permutation-вектора с одинаковой последовательностью `0..N-1` в порядке объектов: 64-битный `$OID$` и 32-битный `FID`. Для popup используется 32-битный `FID`.

## Рабочая цепочка атрибутов

- `cmf-inline-key-v6.js` — резервный прямой декодер номера квартала/выдела.
- `cmf-inline-attrs-v7.js` — основной прямой декодер полной карточки выдела из column streams. Он не меняет геометрию.
- `cmf-pstg-v5.js` + `cmf-attrs-v5.js` — дополнительный compatibility/fallback источник индексированных атрибутов.
- `cmf-label-layer.js` — только MapInfo-style подписи; геометрию и значения не декодирует.
- `map-info.js` — показывает поля в CarryMap-порядке: квартал, выдел, площадь, категория защитности, категория земли, бонитет, тип леса, порода, тон, возраст, высота, диаметр, полнота, запас, хозраспоряжения, проценты, ключ, масштаб учёта, обход, FID.

Правило: последующие улучшения атрибутов не должны менять подтверждённую геометрию `structural-v4` и нумерацию из прямого `Ключ`.
