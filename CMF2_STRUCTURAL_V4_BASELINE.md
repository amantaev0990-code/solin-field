# CMF2 structural-v4 — зафиксированный рабочий baseline

Дата фиксации: 2026-09-07.

Это текущая эталонная архитектура импорта CMF2 для SOLI-N Field. Не заменять её каскадом старых эвристических декодеров без отдельного регрессионного теста.

## Что подтверждено

- Рабочее ядро: `cmf2-structural-v4.js`.
- Геометрические потоки ищутся независимо от описателей слоёв.
- Связь `layer descriptor -> SpatialBlock` определяется структурным инвариантом: отношение масштаба X/Y у реального envelope должно совпадать с отношением масштаба X/Y у агрегированного quantized bbox SpatialBlock.
- Поддерживаются одно- и многоблочные raw-LZ4 потоки с framed length metadata.
- Режим delta-кодирования выбирается по собственным bbox объектов, а не по визуальному совпадению слоёв.
- После сопоставления geometry storage соответствующий `PSTG` блок переназначается правильному векторному слою для дальнейшего чтения атрибутов.
- Старые `universal/adaptive/realign/auto-validator/storage-envelope/native-quantizer/coordinate-fix` не должны возвращаться в активную цепочку как последовательные корректоры геометрии.
- Пользователь подтвердил на неизвестном ранее CMF2, что после перехода на structural-v4 слои встали на свои места. Геометрическое ядро после этого не менять при исправлении подписей/атрибутов.

## Контрольные CMF2

- Богетсайское: 7/7 векторных слоёв, 904 объекта, 39 799 вершин.
- Комсомольское: 7/7 слоёв, 1 352 объекта, 71 641 вершина.

Оба файла являются регрессионными эталонами: любое следующее изменение CMF2-декодера считается допустимым только если они продолжают открываться корректно.

## Точная структура PSTG / SQLite

После отдельного побайтного разбора всех 20 PSTG-блоков двух контрольных CMF2 подтверждено:

- `PSTG` начинается с 4 байт ASCII `PSTG`;
- затем идёт 1 байт версии;
- затем `uint64 little-endian` — полный размер блока PSTG, включая 13-байтовый заголовок;
- с позиции `PSTG + 13` подряд лежат независимые raw-LZ4 потоки SQLite-страниц;
- каждый поток распаковывается ровно в одну SQLite page;
- размер страницы и количество страниц читаются из первой распакованной SQLite-страницы;
- после последней страницы входной курсор в точности совпадает с `PSTG offset + totalBlockBytes`.

Это проверено на 10/10 PSTG Богетсайского и 10/10 PSTG Комсомольского. Старый поиск следующей страницы через `cursor ±12` считать устаревшим. Рабочий декодер: `cmf-pstg-exact-v4.js`.

## Атрибуты и подписи — отдельный слой

Нумерация кварталов/выделов и площади не должны менять координаты.

Текущий слой восстановления: `cmf-attrs-v4.js`. Он выбирает FTS4-базу выделов по двум жёстким признакам: наличие поля `Ключ` и точное совпадение количества документов `idx_docsize` с количеством объектов SpatialBlock.

Ключевой факт CarryMap FTS4: база `idx` является contentless FTS4, поэтому `SELECT count(*) FROM idx` невалиден. Поле `Ключ` индексируется с позициями токенов: для ключа вида `70_5` phrase query `"70 5"` совпадает, а `"5 70"` — нет. Поэтому `Nкварт/Nвыд` восстанавливаются по порядку токенов, а не по названию файла или визуальному расположению.

`cmf-label-layer.js` — только отрисовка MapInfo-style подписей; он не имеет права декодировать или менять геометрию/атрибуты.
