# Зависимые поля таксационной карточки SOLI-N Field

Дата анализа: 29 октября 2026 года. Основа — оригинальная `Solim.mdb`, извлечённые тексты RowSource форм и полный снимок справочников `SOLIN_SOLIM_ALL_USER_TABLE_ROWS_2026-10-11.json.gz`. Анализ выполнен без изменения Access MDB и без запуска VBA. **Это не заявление о 100%-м воспроизведении всего Access.**

## Подтверждено и подключено

| Исходная форма | От чего зависит поле | Оригинальная связь | Что делает Field |
|---|---|---|---|
| ВыделВ → `M3TLU` | главная порода `M3Pr`, хозяйственная зона `KlxrVD`, группа `NE2A`, область `KTOVD` | `STL.GPor=[NM3] AND STL.Lxz=KlxrVD AND STL.GrTL=NE2A AND STL.OblStl=KTOVD` | предлагает только подходящие типы леса, не смешивая области и зоны; неизвестный/неоднозначный контекст не объявляет корректным |
| Квартал → `Klxr` | природная зона `Kpz` | `Slxr.Kpz=Kpz`, `Slxr.Klxz<>0` | список зон меняется от природной зоны; изменённая некорректная комбинация блокируется |
| ВыделВ → `M22` | первое мероприятие `M2PM1` | `SLM.PM2R=0/2`, без дубликата первого, при непустом первом | второй список зависит от первого |
| ВыделВ → `M23` | первое и второе мероприятия | `SLM.PM2R=0/2`, без повторов, при непустом втором | третий список зависит от первых двух |
| ВыделВ → `PRP1–3` | породы подроста | `SDP_Tip.DKP2<700000`, без повторов | последовательные уникальные допустимые породы |
| ВыделВ → `PLP1–3` | породы подлеска | `SDP.DKP2>700000 OR =0`, без повторов | последовательные уникальные допустимые породы |
| Макет 23 → `K1–K8` | предыдущие коды особенности | `SOV.Priz`, уникальность и последовательность | динамический список; исходный SQL `K8` содержит сомнительный строковый литерал, полная эквивалентность не утверждается |
| Макет 12 → `VV/VB` | первый код вредителя/болезни | второе значение не равно первому, `SBR` | исключает повтор; дополнительная зависимость от Access `Признак` пока не реализована |
| Макет 10 → `PROI` | выбранная порода `POR` | `SDP.Происхож`, кроме берёзы | подставляет рекомендованное происхождение при подходящих условиях; берёза заполняется вручную |

## Пример из настоящей базы

Для Бугетсайского лесничества, `KTO=150000000`, `KlxrVD=8`, порода `M3Pr='В'` (вяз), справочник `SDP.ОбПор='В'` и `STL` при `OblStl=15` содержит:

- исходный `KTL='  В'` (пробелы значимы в хранимом TEXT), наименование «Вязовник»;
- `KTL='ВРТЗ'`, наименование «Вязовник».

В обеих строках группа `GrTL=0`. Другие региональные и лесохозяйственные варианты не включаются. На импортированных карточках `NE2A` может отсутствовать: Field разрешает выбор из `STL` без указанной группы **только если в данном сочетании справочник содержит единственную группу**; при нескольких группах сначала требуется уточнение `NE2A`. Оригинальные TEXT-коды с пробелами сохраняются в неизменном виде.

Регион вычисляется по оригинальному `ВыделЛес.KTOKR=[KTO]/10000000`, **только когда это положительный целочисленный код**; иначе Field не делает догадок о регионе. Проверка обращается к `SOLIN_REFS.tables` после загрузки локального справочника, без сервера.

## Безопасность заполнения

- При смене главной породы зависимый список обновляется. Старое недопустимое значение не удаляется из черновика молча, но сохранение изменённой несовместимой комбинации блокируется.
- До загрузки словаря или определения региона поле типа леса недоступно; ранее импортированный код не переписывается.
- Для других лесничеств используются их собственные `KTO`, `KlxrVD`, `M3Pr`, `NE2A`, а не константы из образца 213/2.
- Новые проверки не переписывают исходные файлы `MDB`, служебные поля и названия файлов экспорта.
- Если карточка содержит старое неполное значение, редактирование другого поля не заменяет его автоматически и не маскирует как проверенное.
- Второй редактор дополнительных макетов тоже проверяет зависимые варианты перед записью.

## Где остаются пробелы

Исходные Access `AfterUpdate`, динамические `Признак`, автопересчёт бонитета `M3B`, возраста `AKL/AGR`, запаса `STUR`, лесохозяйственных мероприятий по категории угодий `SKU/SLM`, выбор яруса по `NM1` и дополнительные условия VBA **не объявлены перенесёнными**, пока не доказаны точные вычислительные и событийные правила. Для их внедрения нужны контрольные исходные записи, физические поля и сравнение с изолированной копией рабочего SOLI-N.

Регрессии: `node scripts/test-dependent-field-rules.cjs`, Workflow `.github/workflows/solin-dependent-card.yml`. Пример дерева/типа, региона, зоны, группы и сохранения пробелов протестирован синтетическими fixtures, составленными по конкретным строкам проверенного оригинала. Реальная проверка на iPhone/Access остаётся отдельным этапом.
