## Как работает кнопка
При нажатии проверяется **последний стабильный** GitHub Release в `amantaev0990-code/solin-field`. Его tag должен иметь формат `solin-field-v230004` и увеличиваться для каждой версии, а asset — называться `SOLIN-Field-update.apk` и содержать SHA-256 digest. Если релиза нет, приложение сообщает «Обновлений пока нет». Если он есть, Android-модуль проверяет скачанный файл: HTTPS/домен, SHA-256, совпадение package ID `kz.solin.field.v23build`, **строго увеличенный versionCode**, совпадение сертификата V23. Только затем запускается системный установщик Android. **Обойти подтверждение Android нельзя**. В некоторых устройствах один раз придётся разрешить установку из SOLI-N Field.

## Как впервые активировать
1. В настройках GitHub репозитория → Secrets and variables → Actions → New repository secret, добавить `SOLIN_V23_KEYSTORE_PASSWORD` (пароль из приватной резервной копии V23). Без этого сборка **намеренно блокируется**, и новый ключ не генерируется.
2. GitHub → Actions → **SOLI-N Field — signed GitHub updater release** → Run workflow, `version_code=230004`, `publish=false`. После успешной сборки скачать `SOLIN-Field-update.apk` из артефактов и проверить на одном устройстве: загрузка и экспорт MDB, лесничества, кварталы, выделы, районы, ЕШ/тип леса, расчёты и работа офлайн. Перед установкой сохранить резервный экспорт MDB.
3. Убедиться, что новая версия действительно обновляет V23 **поверх** неё, а не просит удалить старую. Проверить, что данные остались.
4. Для последующих версий запускать workflow с **более высоким** `version_code` и публиковать `publish=true` только после тестов. GitHub Releases в **публичном репозитории публичны**: любой сможет скачать APK и извлечь встроенные данные, как из обычного APK. Учитывать лицензионные права.
5. После публикации новой версии на установленном Android-приложении во вкладке «Ещё» нажать «Проверить обновления». Оно скачает APK и предложит подтверждение установки.

## Защита от ошибок
- Старые V22 не являются целью обновления. Используется **только** `kz.solin.field.v23build` и неизменный сертификат V23.
- Никогда не изменять `versionCode` вниз и не генерировать новые signing keys.
- Исходный V23 **не изменяется**, пока не установлена и не проверена первая сборка с модулем обновлений.
- Успех unit/compile тестов **не** заменяет тест на реальном планшете. Автоматически публиковать релиз без проверки нельзя.
