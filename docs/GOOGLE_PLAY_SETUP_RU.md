# SOLI-N Field — подготовка к Google Play (внутреннее тестирование)

## Уже подготовлено
В репозитории есть ручной workflow `.github/workflows/solin-google-play-internal-aab.yml`. Он собирает **AAB** из ветки `fix/v23-field-test-2026-11-06`, сохраняет Android ID `kz.solin.field.v23build`, повышает target/compile SDK до 36 и использует **существующий ключ V23** как ключ загрузки (upload key). Новый ключ не генерируется. Готовый AAB сохраняется как артефакт GitHub Actions; сам workflow ничего в Play Console не публикует.

## Действия владельца Play Console
1. Создать или открыть аккаунт на https://play.google.com/console. Регистрационный сбор обычного Play Console: **25 долларов единовременно**, может потребоваться подтверждение личности.
2. В GitHub → Settings → Secrets and variables → Actions → Repository secrets установить `SOLIN_V23_KEYSTORE_PASSWORD` из приватного резервного архива V23. Никогда не публиковать пароль, JSON с паролем или резервный ZIP в репозитории. Если секрет не задан, workflow остановится.
3. GitHub → Actions → **SOLI-N Field — Google Play internal testing AAB** → Run workflow. Версия для первого тестового релиза: `versionCode=230003`; при повторных загрузках увеличивать номер. Скачать `SOLIN-Field-Play.aab` из артефактов запуска.
4. В Play Console создать приложение **SOLI-N Field**, выбрать **Internal testing**, добавить Google-аккаунты тестировщиков, загрузить AAB. Далее заполнить обязательные формы Play Console: контакт, описание, скриншоты, категории, Data safety, политика конфиденциальности, сведения о доступе к местоположению и файлам. Все ответы должны отражать реальное поведение приложения; публикация зависит от Google.
5. **До первой публикации** выбрать режим Play App Signing. Если нужно обновление поверх APK V23 без потери данных, использовать оригинальный сертификат подписания **V23** для подписи приложений Google Play через официальную процедуру импорта существующего ключа (PEPK) и проверить SHA-256. Если Google сам создаст отдельный app-signing key, установка из Play поверх вручную установленной V23 может быть невозможна. Тогда сначала экспортировать полевые данные и выполнить один контролируемый переход.
6. Получить в Play Console ссылку приглашения для тестировщиков и установить приложение через Google Play. Последующие обновления через магазин могут устанавливаться автоматически при включённых автообновлениях.

## Важные особенности
- Ключ **загрузки** и ключ **подписи приложений Google Play** — разные роли. Google управляет ключом подписи распространяемых пользователям APK; файл V23 сейчас применяется для подписи загружаемого AAB.
- Новые обычные приложения в ноябре 2026 года должны целиться в Android 16 / API 36 или выше.
- Для личных аккаунтов Play Console, созданных после 13 ноября 2023 года, выпуск в production может потребовать закрытого тестирования (12 тестировщиков/14 дней). Для нашей начальной цели используем внутренний тест.
- Прежде чем передавать полевые материалы через магазин, проверить права на исходные данные и библиотеки, а также полноту работы MDB в тестовой сборке.
