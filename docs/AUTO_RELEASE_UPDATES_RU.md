# SOLI-N Field — автоматические подписанные APK-обновления

## Что теперь автоматизировано

Файл workflow: `.github/workflows/solin-auto-release.yml`.

После запуска выпускного сценария GitHub Actions сам:
1. Забирает указанный **проверенный исходный коммит** SOLI-N Field.
2. Прогоняет тесты обновлялки, расчётов, справочников и совпадения WebView с APK.
3. Собирает **неподписанный APK** без доступа к паролю.
4. В отдельном задании возвращает оригинальный зашифрованный справочник и подписывает существующим ключом V23.
5. Проверяет package ID, versionCode, сертификат SHA-256, справочник и итоговый APK.
6. Сохраняет подписанный кандидат и, при явном разрешении или выпускном Git-теге, публикует `SOLIN-Field-update.apk` + `SHA256SUMS.txt` в публичных GitHub Releases.

**Вручную прикладывать APK к каждому релизу больше не требуется.**

## Единственная предварительная настройка

В GitHub → Settings → Secrets and variables → Actions должен существовать секрет
`SOLIN_V23_KEYSTORE_PASSWORD`, содержащий пароль оригинального V23 из личной резервной копии `V23_PRIVATE_SIGNING_BACKUP.zip` / `signing-private.json`.

[Открыть GitHub Actions Secrets](https://github.com/amantaev0990-code/solin-field/settings/secrets/actions)

Пароль нельзя публиковать в репозитории, сообщениях, Issue или логах.
Если секрета нет, сборка *намеренно блокирует* подпись. Новый ключ создавать запрещено:
обновление поверх установленных V23–V30 тогда перестанет работать.

## Как запускать, когда готова следующая версия

[Открыть workflow](https://github.com/amantaev0990-code/solin-field/actions/workflows/solin-auto-release.yml)

**Вариант с проверкой кандидата**: Actions → SOLI-N Field - signed automatic updates → Run workflow.
Выбрать ветку/коммит с реальными новыми исходниками, оставить `version_code=auto` (номер увеличится автоматически, начиная с 230011), установить `publish=false`.
После зелёной сборки забрать тестовый подписанный APK из Artifacts и проверить на планшете
*поверх* установленной версии, с предварительной резервной копией данных.

**Публикация без ручной загрузки**: повторить Run workflow с `publish=true`, либо создать Git-тег вида
`solin-field-v230011` на проверенном исходном коммите (число должно повышаться).
Если исходный тег содержит этот workflow, push тега автоматически запускает сборку/подпись/публикацию.
Защитные проверки по-прежнему обязательны.

## Что увидит пользователь на планшете

В установленной версии с работающим Android-модулем: «Ещё» → «Проверить обновления».
Модуль получает последний *стабильный* GitHub Release, проверяет SHA-256,
цифровую подпись, package ID и более высокий номер версии и запускает системный установщик.
**Android всегда запрашивает подтверждение установки**, а иногда и разовое разрешение
«Установка из этого источника». Данные сохраняются при обновлении без удаления приложения.

## ВАЖНО: переход с установленной V29

В репозитории сейчас опубликована только V25; локально собранная V30 APK
**не является GitHub-релизом**, пока её не опубликовали.
Этот новый workflow не может автоматически восстановить исходники V30 из локального APK:
для релиза нужно иметь точный проверенный исходный код в Git.
Не выдавать повторную сборку кода V29 за полноценную V30.
Не публиковать выпуск на основе старой ветки только ради увеличения versionCode.
V29 не удалять. Перед первым обновлением экспортировать резервную копию полевых данных
и убедиться, что размер файла больше нуля.

## Публичность

Репозиторий и GitHub Releases публичны: опубликованный APK может скачать любой пользователь.
Перед коммерческим распространением проверить права на встроенные справочники.
